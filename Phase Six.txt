# Phase 6 — WhatsApp Business API & Webhook Automation

Telecalling CRM · Technical implementation specification · Multi-Channel Follow-up Automation

Phase 6 introduces official enterprise WhatsApp messaging to the Telecalling CRM on top of the native Kotlin telephony engine (Phase 1), NestJS backend core (Phase 2), offline-first caller mobile app (Phase 3), manager web dashboard (Phase 4), and automated queue dialer (Phase 5). 

While Phase 5 enabled telecallers to maintain a high-velocity calling rhythm across 50-lead shift queues, telecallers often lose prospect momentum after hanging up. Prospects requesting a brochure, solar subsidy calculation, site inspection confirmation, or quotation rarely take immediate action unless documentation arrives on their primary messaging channel within seconds of the call ending.

Phase 6 implements the **Official WhatsApp Cloud API Engine**: integrating pre-approved Meta message templates, disposition-triggered automatic dispatches, cryptographic webhook delivery receipts (`SENT`, `DELIVERED`, `READ`, `FAILED`), DPDP-compliant consent tracking, automated `STOP` / `UNSUBSCRIBE` keyword opt-out processing, and real-time status tick badges across both the mobile caller app and supervisor web timeline.

Your master plan allocates approximately 2 weeks to this phase.

## 1. What are we building in Phase 6?

We are building the complete **WhatsApp Business Automation & Inbound Delivery Receipt Engine** spanning the **NestJS Backend (`apps/api`)**, **React Native Caller App (`apps/mobile`)**, and **Next.js Manager Dashboard (`apps/web`)**.

The messaging engine encompasses seven core capabilities:

- **1. Meta WhatsApp Cloud API Client & Configuration Service:**
  - Robust HTTPS client communicating with Meta Graph API (`v21.0`).
  - Supports Bearer Token authorization, system phone number ID, and business account ID.
  - Safe Mock & Development Sandbox mode (`cfg_whatsapp_sandbox: "true"`) allowing 100% offline and staging test verification without consuming Meta conversation credits or disturbing real numbers.

- **2. Standard Pre-Approved Solar Template Registry:**
  - `solar_brochure_v1`: Instant digital company profile and rooftop solar subsidy guide.
  - `solar_quote_followup_v1`: Customized kW system sizing and pricing breakdown.
  - `site_inspection_confirm_v1`: Date, time, and technician details for rooftop solar survey.
  - `callback_scheduled_v1`: Reassurance message noting rescheduled callback appointment.
  - Dynamic parameter interpolation (`{{name}}`, `{{kw}}`, `{{date}}`, `{{phone}}`, `{{agent}}`).

- **3. Post-Call Disposition Automated Dispatch Pipeline:**
  - Seamlessly hooked into the Two-Tap Disposition modal in `apps/mobile`:
    - Outcome `Connected` + Disposition `Interested` automatically queues `solar_brochure_v1`.
    - Outcome `Connected` + Disposition `Meeting Scheduled` automatically queues `site_inspection_confirm_v1`.
    - Outcome `Connected` + Disposition `Follow-up Required` automatically queues `callback_scheduled_v1`.
  - Checkbox toggle: telecaller can preview, alter, or uncheck the automated dispatch before tapping "Save & Next".

- **4. Cryptographic Webhook Receiver (`/api/webhooks/whatsapp`):**
  - `GET /api/webhooks/whatsapp`: Responds to Meta verification handshake (`hub.mode=subscribe`, `hub.verify_token`, `hub.challenge`).
  - `POST /api/webhooks/whatsapp`: Verifies incoming HMAC-SHA256 signature (`X-Hub-Signature-256`) against app secret.
  - Monotonic status advancement in `MessageLog`: `SENT` ➔ `DELIVERED` ➔ `READ` (or `FAILED` with provider error code).

- **5. Inbound Opt-Out & Regulatory DPDP Consent Engine:**
  - Validates `Consent` record where `type = WHATSAPP` and `revoked = false` before any template dispatch.
  - Inbound webhook parser detects customer replies containing `STOP`, `UNSUBSCRIBE`, `OPT OUT`, or `DON'T MESSAGE`.
  - Automatically flags lead with `dnd: true`, marks `Consent.revoked = true`, logs an audit entry, and excludes prospect from future auto-dial and messaging queues.

- **6. TRAI Calling-Hours Guardrail (9:00 AM – 8:00 PM IST):**
  - Strict time check prevents automated nocturnal template sends.
  - If a call is dispositioned outside hours, dispatch is held in pending status until the next business morning at 9:01 AM IST (or telecaller can tap explicit manual override).

- **7. Multi-Platform Real-Time Status Tick Badges:**
  - **Caller Mobile App (`apps/mobile`):** Shows double grey tick (`DELIVERED`) and double blue tick (`READ`) directly on lead preview cards and call history logs.
  - **Manager Web Dashboard (`apps/web`):** Embeds WhatsApp message timeline cards within the Chronological Lead Activity view (`GET /leads/:id`).

### Task 1 — Meta Cloud API Client & Sandbox Mock Engine
**Timeline:** Days 1–3  
**Goal:** Build a robust, resilient HTTP client interfacing with the Meta WhatsApp Cloud API (`https://graph.facebook.com/v21.0/`).

- **Subtasks:**
  1. Author `WhatsAppClient` inside `MessagesService` supporting `POST /{phone_number_id}/messages`.
  2. Implement Bearer token authorization using `WHATSAPP_ACCESS_TOKEN` and `WHATSAPP_PHONE_NUMBER_ID`.
  3. Add Safe Mock & Sandbox Mode (`cfg_whatsapp_sandbox: "true"`): when sandbox mode is active, simulate Meta responses with realistic `wamid.HBg...` IDs without burning API credits or making external HTTP network calls during tests.
  4. Implement exponential backoff retry for transient network errors (HTTP 429, 500, 503).
- **Acceptance Criteria:**
  - Client sends valid Meta JSON payloads matching Graph API v21.0 specs.
  - Sandbox mode cleanly simulates responses in local test environments.

### Task 2 — Standard Solar Templates Registry & Seeding
**Timeline:** Days 3–5  
**Goal:** Seed and support the 4 standard pre-approved solar sales templates with dynamic parameter interpolation.

- **Subtasks:**

     - `solar_brochure_v1`: Welcome & high-resolution rooftop solar guide PDF.
     - `solar_quote_followup_v1`: Estimated project kW sizing, subsidy amount, and net cost.

### Task 3 — Inbound Webhook Handshake & Signature Security
**Timeline:** Days 5–7  
**Goal:** Establish the official Meta Webhook receiver with cryptographic signature validation.

- **Subtasks:**
  1. Implement `GET /api/webhooks/whatsapp`:
     - Validates `hub.mode === 'subscribe'` and `hub.verify_token === WHATSAPP_WEBHOOK_VERIFY_TOKEN`.
     - Returns `hub.challenge` as plain text with HTTP 200.
     - Rejects invalid tokens with HTTP 403 Forbidden.
  2. Implement `POST /api/webhooks/whatsapp`:
     - Parses status array (`statuses[].status`: `sent`, `delivered`, `read`, `failed`).
     - Updates `MessageLog.status` and logs error codes for failed deliveries.
- **Acceptance Criteria:**
  - Webhook responds to verification challenges instantly.
  - Status updates monotonically update message state in PostgreSQL.

### Task 4 — DPDP Consent Check & Inbound STOP Auto-DND
**Timeline:** Days 7–9  
**Goal:** Ensure 100% legal compliance with DPDP and TRAI regulations by strictly vetting recipient consent and honoring opt-outs.

- **Subtasks:**
  1. Before dispatching any message, query `Consent`:
     - Reject if `Consent.type = 'WHATSAPP'` and `revoked = true` with `403 Forbidden`.
  2. Inbound message reply parser:
     - Detect keywords: `STOP`, `UNSUBSCRIBE`, `OPT OUT`, `DON'T MESSAGE`, `NO`.
     - Automatically update `Lead.dnd = true` and set `Consent.revoked = true`.
     - Log an audit trail entry in `LeadAssignment` / `CallLog`.
  3. Automatically exclude lead from auto-dialer queues and upcoming message dispatches.
- **Acceptance Criteria:**
  - Revoked consent halts message dispatch 100% of the time.
  - Sending `STOP` flags prospect with DND instantly.
