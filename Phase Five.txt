# Phase 5 — Auto-Dialer & Calling Queue Engine

Telecalling CRM · Technical implementation specification · Mobile-first Automation

Phase 5 builds the automated calling engine on top of the Phase 1 native Kotlin Telephony Engine, Phase 2 NestJS backend core, Phase 3 telecaller mobile app, and Phase 4 manager web dashboard. While Phase 3 delivered manual single-lead calling and two-tap dispositions, and Phase 4 established live shift oversight and S3 recording auditing, telecallers dialing manually often spend 30 to 60 seconds between calls hesitating, reviewing contact lists, or getting distracted.

Phase 5 introduces **Automated Queue Dialing Mode** (Auto-Dialer) inside the mobile application. This turns the telecaller's shift into an automated, rhythmic sales pipeline: the app loads the prioritized shift queue from local SQLite, presents the lead preview card with the mandatory DPDP verbal recording disclosure, runs an animated countdown ring timer with adjustable pacing gap (3s, 5s, 8s, 10s), places the call through the chosen SIM, detects call completion, automatically foregrounds the two-tap disposition sheet, and upon tapping "Save & Next", instantly transitions to the next prospect in queue.

Your master plan allocates approximately 2 weeks to this phase.

## Phase 5 exit criteria

# 0
Live cellular calls placed during automated verification (enforced via default Safe Simulation Mode)

# ≥35%
Increase in connected talk time and completed dials per shift compared to manual dialing

# 100%
Queue integrity with zero skipped leads or duplicate dials across network drops or backgrounding

# <100ms
Auto-advance transition latency between disposition submission and next lead preview countdown

# 4
Configurable pacing gap durations supported (3s, 5s, 8s, 10s) with instant Pause, Skip, and Stop controls

These criteria guarantee that telecallers can maintain a sustained, fatigue-free dialing rhythm while strictly honoring calling-hours rules, DND flags, and DPDP/TRAI regulatory disclosures.

## 1. What are we building in Phase 5?

We are building the complete **Auto-Dialer Queue Engine** inside `apps/mobile` using **React Native**, **TypeScript**, and **Lucide Plane Outline Icons**, interfacing directly with the native Kotlin telephony engine (`modules/telephony-engine`), `expo-sqlite`, and the NestJS backend API.

The auto-dialing engine encompasses seven core capabilities:

- **1. Auto-Dial Session Orchestrator & State Machine:**
  - Robust local finite state machine managing nine explicit states: `IDLE`, `QUEUE_LOADED`, `LEAD_PREVIEW`, `COUNTDOWN`, `DIALING`, `IN_CALL`, `DISPOSITION`, `ADVANCING`, `PAUSED`, and `COMPLETED`.
  - Survives app backgrounding, screen timeout, incoming interruption calls, and network disconnects without losing session position.

- **2. Circular Animated Countdown Timer Ring:**
  - Smooth visual countdown ring (SVG / Reanimated) with second-by-second countdown and subtle haptic feedback on each tick.
  - Gives the telecaller a clear, predictable window to read prospect context (name, estimated kW solar load, previous call remarks) before the dial is triggered.

- **3. Interactive Pacing Gap Selector:**
  - Adjustable pause gap between calls:
    - **3 Seconds:** Aggressive mode for high-energy telecallers on short cold-lead lists.
    - **5 Seconds (Default):** Standard recommended pacing balancing focus and breathing room.
    - **8 Seconds:** Relaxed pacing for complex residential & commercial solar proposals.
    - **10 Seconds:** Training mode for new telecaller onboarding.
  - Selected pacing gap persisted locally in SQLite `sync_meta` across sessions.

- **4. Instant Telecaller Control Deck:**
  - **Pause / Take Break:** Pauses the session cleanly (e.g. for note-taking, water break, or bathroom pause).
  - **Skip Lead:** Defers the current prospect to the end of the shift queue without burning a dial attempt.
  - **Dial Now:** Bypasses remaining countdown seconds to trigger the call immediately.
  - **Stop / Exit Queue:** Gracefully ends the session, committing all progress and returning to the Home dashboard.

- **5. Post-Call Auto-Advance Pipeline:**
  - Upon call termination (detected via Kotlin `TelephonyCallback` / `PhoneStateListener`), the app automatically wakes to the foreground and presents the **Two-Tap Call Disposition Sheet**.
  - **Tap 1:** Outcome selection (`Connected`, `Busy`, `Not Picked`, `Switched Off`).
  - **Tap 2:** Business disposition (`Interested`, `Follow-up`, `Meeting`, `Lost`).
  - Tapping **"Save & Next"** applies the optimistic mutation to SQLite, enqueues the outbox sync job, increments session counters, and immediately advances to the next lead's countdown.

- **6. Session Velocity HUD & Target Progress:**
  - Floating header HUD displaying:
    - Current Session Dials (e.g. `14 / 40`).
    - Connect Rate % for the current session.
    - Total Session Talk Time.
    - Remaining Leads in Queue.
  - Synchronized with the Daily Target Progress Ring on the Home screen.

- **7. Regulatory, Calling-Hours & Hardware Guardrails:**
  - **TRAI Calling Hours Window (9:00 AM – 8:00 PM IST):** Dialing automatically disables outside official calling hours.
  - **DND & Opt-Out Filter:** Any prospect flagged with `dnd: true` is strictly omitted from the auto-dial queue.
  - **Battery & Thermal Throttler:** If battery drops below 15% or device experiences extreme thermal throttling, the auto-dialer safely pauses and alerts the caller.
  - **Safe Simulation Mode:** Always active by default (`cfg_simulation_mode: "true"`) during development and testing to prevent unauthorized calls to real numbers.

### Task 1 — Auto-Dialer State Machine & Queue Cursor Manager
**Timeline:** Days 1–3  
**Goal:** Create a rock-solid finite state machine that sequences leads from local SQLite without race conditions or skipped prospects.

- **Subtasks:**
  1. Define explicit state types in `useAutoDialer.ts`: `IDLE`, `LEAD_PREVIEW`, `COUNTDOWN`, `DIALING`, `IN_CALL`, `DISPOSITION`, `ADVANCING`, `PAUSED`, `COMPLETED`.
  2. Implement SQLite queue query prioritizing due callbacks first, followed by fresh uncalled leads sorted by `priority DESC, createdAt ASC`.
  3. Support session lifecycle: `startSession(pacingGapSec)`, `pauseSession()`, `resumeSession()`, `skipCurrentLead()`, `stopSession()`.
  4. Preserve cursor state in `sync_meta` so that if the caller answers an incoming call or navigates away, the session resumes at the exact current lead.
- **Acceptance Criteria:**
  - State transitions follow strict DAG ordering without invalid skips.
  - Queue loads 50 leads in <20ms from local `expo-sqlite`.

### Task 2 — Circular Countdown Ring & Haptic Timer Component
**Timeline:** Days 3–5  
**Goal:** Build an engaging, high-contrast visual countdown ring that gives the telecaller clear visual feedback before each call is placed.

- **Subtasks:**
  1. Author `CountdownRing.tsx` using SVG circle with animated `strokeDashoffset` corresponding to remaining seconds.
  2. Display large, high-legibility second counter in center of ring (e.g. `5`, `4`, `3`, `2`, `1`).
  3. Integrate subtle device vibration / haptic feedback on each second decrement (`Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)`).
  4. Add visual color transitions: Indigo during countdown, Green on dial trigger, Amber when paused.
- **Acceptance Criteria:**
  - Countdown animates smoothly at 60 FPS without UI jank.
  - Reaching zero immediately fires the `TRIGGER_DIAL` action.

### Task 3 — Pacing Gap Selector & Session Persistence
**Timeline:** Days 5–7

### Task 5 — Two-Tap Disposition & Auto-Advance Pipeline
**Timeline:** Days 9–12  
**Goal:** Deliver a frictionless loop where saving a call outcome instantly advances to the next lead without manual queue navigation.

- **Subtasks:**
  1. Listen to `TelephonyEngine.onCallEnded` event.
  2. Instantly wake app to foreground and auto-open `DispositionModal.tsx`.
  3. Pre-select detected call outcome (`CONNECTED` if duration >0s, else `NOT_PICKED`).
  4. Telecaller taps business disposition (`Interested`, `Follow-up`, `Meeting`, `Lost`).
  5. Telecaller taps primary CTA button **"Save & Next →"**:
     - Writes call log and disposition to SQLite and Room outbox.
     - Enqueues background sync job via WorkManager.
     - Increments session dials counter.
     - Transitions state machine to `ADVANCING`.
     - Loads next lead and starts countdown timer.
- **Acceptance Criteria:**
  - Transition from "Save & Next" to next lead preview occurs in <100ms.
  - Zero lost calls or orphaned dispositions.
